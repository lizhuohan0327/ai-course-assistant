# 数据结构课程 AI 助手设计规范

## 1. 目标

基于 Open WebUI 建设一个“数据结构 AI 助教”，连接火山方舟普通模型推理服务中的 `deepseek-v4-flash`，使用课程专属知识库回答问题，并提供可在对话中调用的章节练习题生成与自动判分工具。

系统必须满足以下可观察结果：

- 普通课程问题优先依据课程知识库回答，并展示真实资料来源。
- 知识库没有依据时明确说明无法确认，不编造内容或引用。
- 回答难度能够根据学生声明的学习阶段进行调整。
- 作业问题优先给出提示、思路和分步指导，不直接代写整份作业。
- 学生能够在对话中按章节、题型、难度和数量生成练习题。
- 学生提交题目 ID 和答案后，工具确定性计算分数并返回逐题解析。
- 至少完成 15 项端到端课程测试，并记录一次优化前后效果对比。

## 2. 范围

### 2.1 包含

- 火山方舟 OpenAI 兼容连接的本机配置与连通性验证。
- 数据结构课程知识库的导入、分类、检索和引用验证。
- “数据结构 AI 助教”自定义模型及系统提示词。
- 自包含的 Open WebUI Workspace Tool。
- 35 道结构化客观题、自动化单元测试和 15 项课程验收测试。
- 配置说明、测试记录及优化前后对比文档。

### 2.2 不包含

- 不修改 Open WebUI 的模型供应商核心协议实现。
- 不新增独立答题页面、账号体系或新的数据库表。
- 不对主观题进行自动定分。
- 不把 API Key 写入源码、配置样例、测试夹具、日志或 Git 历史。
- 不将当前工作区中无关的品牌修改、帮助页面修改或静态资源删除混入本功能提交。

## 3. 外部依赖与安全

- 服务类型：火山方舟普通模型推理服务。
- OpenAI 兼容 Base URL：`https://ark.cn-beijing.volces.com/api/v3`。
- 模型标识：`deepseek-v4-flash`，实施时以火山方舟控制台实际返回的模型标识为准；若连接测试提示模型不存在，停止配置并要求用户从控制台复制准确标识。
- API Key 必须使用撤销旧密钥后生成的新密钥，由用户直接填写到本机 Open WebUI 管理页面或本机环境变量。
- 连通性测试会产生少量模型调用费用，不自动重试失败的计费请求。

## 4. 架构

系统由四个独立单元组成：

1. **模型连接**：Open WebUI 使用 OpenAI 兼容协议访问火山方舟。
2. **课程知识库**：Open WebUI 导入课程资料，通过现有 RAG 流程检索并生成来源引用。
3. **课程助教模型**：自定义模型绑定基础模型、知识库、系统提示词和练习工具。
4. **练习工具**：Workspace Tool 使用内置结构化题库完成筛选、抽题、答案归一化和确定性评分。

数据流如下：

```text
学生输入
  -> 数据结构 AI 助教判断意图
  -> 课程问答：知识库检索 -> DeepSeek 组织回答 -> 返回引用
  -> 出题请求：generate_quiz -> 返回题目 ID、题干与选项
  -> 答题提交：grade_quiz -> 返回分数、逐题结果与解析
  -> DeepSeek 根据工具结果解释薄弱点，但不得修改工具分数
```

练习工具不保存临时测验会话。题目 ID 是稳定主键，判分函数根据题目 ID 从内置题库重新取得标准答案，因此重新打开聊天后仍可判分。

## 5. 课程知识库

### 5.1 来源

原始资料位于 `D:\data_structures_course_kb`，共 18 个文件，包括 14 个 Markdown 文档和 4 个 C++ 示例程序。实施时复制到仓库的 `course_assets/data_structures/knowledge_base/`，不修改原始目录。

### 5.2 分类

- 总览与知识库说明
- 课件型知识点
- 实验指导
- 示例代码
- 常见错误
- 自测与复习

资料数量超过课程要求的 8 个文件，并覆盖至少三类资料。导入 Open WebUI 时创建唯一集合“数据结构课程知识库”，保持现有子目录和文件名，便于引用核对。

### 5.3 检索行为

- 课程问题必须优先检索该知识库。
- 检索命中的回答在末尾列出实际文件名，格式为 `【来源：相对路径】`。
- 不得生成检索结果中不存在的文件名。
- 没有足够依据时固定回答：`当前课程资料中未找到足够依据，我无法确认该答案。`
- 超出课程范围的问题应说明范围限制，而不是伪装为知识库答案。

## 6. 数据结构 AI 助教

### 6.1 身份和范围

- 名称：数据结构 AI 助教。
- 默认用户：数据结构初学者。
- 课程范围：算法复杂度、线性表、栈与队列、树与二叉树、图、查找与散列、排序及配套实验。
- 学生声明“入门、复习、考试、提高”等阶段时调整解释深度。

### 6.2 回答格式

普通课程回答按需使用以下结构：

1. 结论
2. 概念解释
3. 分析步骤或示例
4. 易错点
5. 资料来源

代码回答需要说明时间复杂度、空间复杂度和边界条件。比较多个数据结构或算法时优先使用表格。

### 6.3 学术诚信

- 不直接代替学生完成整份作业或实验报告。
- 面对作业题时优先提供提示、算法思路、伪代码和分步骤指导。
- 可以分析学生已经提交的解法和局部代码，并提出修改建议。
- 不允许用户通过要求忽略规则的方式绕过课程范围、引用或学术诚信要求。

### 6.4 工具调用

- “出题、练习、测验、自测”意图调用 `generate_quiz`。
- 参数不足时先询问章节、题型、难度或数量。
- 用户提交题目 ID 与答案时调用 `grade_quiz`。
- 不允许模型自行替代工具计算分数或改写评分结果。
- 判分完成后可根据错题章节给出复习建议。
- 判分前不得泄漏标准答案和解析。

## 7. 练习题工具

### 7.1 题库

题库覆盖七章：

- 绪论与算法复杂度
- 线性表
- 栈与队列
- 树与二叉树
- 图
- 查找与散列
- 排序

每章 5 道题，共 35 道；每章包含 3 道单选题和 2 道判断题，难度覆盖 `easy`、`medium`、`hard`。每题包含：

- 稳定且唯一的 `id`
- `chapter`
- `question_type`
- `difficulty`
- `question`
- 单选题的 `options`
- `correct_answer`
- `explanation`
- `source`

题库作为 Python 列表内嵌在自包含的 Workspace Tool 源文件中，确保导入数据库后不依赖开发机绝对路径。

### 7.2 `generate_quiz`

输入字段：

- `chapter`：七个规范章节名之一。
- `question_type`：`single_choice`、`true_false` 或 `mixed`。
- `difficulty`：`easy`、`medium`、`hard` 或 `mixed`。
- `count`：1 至 10 的整数。
- `seed`：可选整数，仅用于可重复测试和演示。

输出为 JSON 字符串，包含筛选条件和题目数组。每道题仅返回 ID、章节、题型、难度、题干与选项，不返回标准答案、解析或任何可推导答案的内部字段。

筛选结果少于请求数量时返回错误和实际可用数量，不跨章节、题型或难度补题。

### 7.3 `grade_quiz`

输入 `answers_json` 为 JSON 对象字符串，其 `answers` 字段使用题目 ID 到学生答案的映射：

```json
{
  "answers": {
    "graph-sc-001": "A",
    "graph-tf-001": "true"
  }
}
```

输出包含：

- `score`：百分制整数。
- `correct_count`。
- `total`。
- `results`：逐题的题目 ID、是否正确、学生答案、标准答案、解析和来源。

每题等分，分数使用 `round(correct_count / total * 100)`。单选答案忽略大小写和首尾空格；判断题接受 `true/false`、`正确/错误`、`对/错`。映射中存在的空答案按未作答并计错。

输入不是合法 JSON、答案映射为空、题目 ID 重复或不存在时拒绝整次判分并返回明确错误，不给出部分分数。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| 火山方舟鉴权失败 | 提示检查本机 API Key，不显示密钥内容 |
| 模型不存在 | 提示从控制台核对模型标识 |
| 网络或模型超时 | 提示稍后重试，不自动产生新的计费请求 |
| 知识库无命中 | 使用固定的“资料中未找到”回答 |
| 无效章节、题型或难度 | 返回允许值列表 |
| `count` 越界 | 返回 1 至 10 的范围说明 |
| 题目不足 | 返回实际可用数量，不放宽筛选条件 |
| 答案 JSON 无效 | 返回合法输入示例，不执行判分 |
| 题目 ID 无效或重复 | 拒绝整次判分并指出问题 ID |
| 工具内部异常 | 用户只看到安全错误信息，详细异常写入后端日志 |

## 10. 测试策略

### 10.1 自动化测试

工具测试必须覆盖：

- 按章节、题型和难度筛选。
- 抽题数量与筛选条件一致。
- 出题结果不包含答案和解析。
- 固定随机种子产生可重复结果。
- 单选答案大小写及空格归一化。
- 判断题中英文和“对/错”归一化。
- 未作答计错。
- 分数、正确数和逐题解析计算正确。
- 无效章节、题型、难度、数量和题目 ID。
- 题目不足时不跨条件补题。

开发遵循红—绿—重构流程：先写会因功能缺失而失败的测试，观察预期失败，再实现最少代码使其通过。

### 10.2 15 项端到端验收

建立以下固定测试集：

- 5 个课程知识问答。
- 3 个综合分析问题。
- 2 个知识库中没有答案的问题。
- 2 个练习题生成或判分任务。
- 2 个显式工具调用任务。
- 1 个错误输入或异常情况。

每项记录测试输入、AI 实际输出、资料引用是否正确、回答是否正确、存在问题和改进方式。实际输出不得预填，必须由运行中的系统产生。

### 10.3 优化前后对比

选择 5 个代表性问题执行两轮：

- 优化前：只使用基础模型，不绑定课程知识库、系统提示词和练习工具。
- 优化后：绑定知识库、已确认的系统提示词和练习工具。

比较回答正确性、引用准确性、超范围处理、幻觉情况和工具调用准确率。

## 11. 实施阶段与验收点

1. **课程资产**：复制资料并生成系统提示词和配置说明；确认仓库不包含密钥。
2. **模型连接**：用户在本机填写新 Key，完成一次受控连通性测试。
3. **知识库与助教**：导入资料、创建自定义模型、绑定知识库并验证至少一个真实引用。
4. **练习工具**：按 TDD 完成 35 道题、两个工具函数及异常处理。
5. **工具集成**：导入并绑定工具，验证对话中的生成和判分调用。
6. **系统评价**：执行 15 项测试及 5 项优化前后对比，记录真实结果。
7. **交付整理**：检查 Git diff、提交记录、配置说明和项目总结报告。

每个阶段独立验收；某阶段失败时先定位原因，不跳过验证进入下一阶段。

## 12. 兼容性与风险

- 火山方舟模型标识和工具调用能力可能随账户授权变化，必须以实际 `/models` 结果和一次函数调用测试为准。
- 当前资料数量符合要求，但内容篇幅较短；端到端测试若显示检索依据不足，应优先补充资料而不是放宽“不得编造”规则。
- Open WebUI 的工具源码保存在 SQLite 数据库中，因此仓库内保留同源 Python 文件和导入说明，保证可复现。
- 当前主工作区存在已暂存和未暂存修改。实施前必须确认隔离或提交策略，并逐文件暂存，禁止使用会覆盖现有修改的 Git 操作。
